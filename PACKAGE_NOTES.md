# Package notes: how this package differs from the private working folders

This is a **private review copy**. No licence is granted yet; ownership and co-author permissions will be reviewed before any wider distribution.

## Personal-path sanitisation (distribution copies only)

The original project and the reproduction folder stay unchanged on the author's computer. In this package only, one mechanical rule was applied to every text file:

| Original text | Package text |
| --- | --- |
| the Windows account name in `C:\Users\…\` paths (also in their JSON-escaped and forward-slash forms) | `<user>`, giving `C:\Users\<user>\` |

- **Changes:** nothing else was edited. Line numbers, code, comments, values and file names are unchanged.
- **Per-file record:** `manifests/sanitisation_map.csv` lists every sanitised file with its SHA-256 in the package, the SHA-256 of the private file it came from, and the number of replacements. Anyone holding the private files can therefore check that the only difference is this substitution.
- **Checks at build time:** the build verified this for every file (`evidence/package_build/verification.json`). For the 19 scripts it also checked that each one's Python syntax tree matches its private original after normalisation of the permitted path-string literals.
- **Files left out:**
  - the PowerShell transcripts of the verified runs, which record the Windows account and computer name (the per-step logs keep the same commands and output);
  - the setup transcript.

## What is not shipped

| Not shipped | Why | How to get it |
| --- | --- | --- |
| Raw BRFSS and NHANES data | Public CDC data; large | `DATA.md` (sources and checksums) |
| 13 row-level BRFSS prediction files (116 MB): proposed model's out-of-fold file and ablation components, 11 baseline out-of-fold files | Size | Regenerated by Stages 2–3; SHA-256 in `manifests/excluded_files.sha256`; checked with `python tools/verify_package.py --check_excluded` |
| 3 derived NHANES CSVs | Derived from the public data | Regenerated by Stage 1; SHA-256 in the same manifest |
| Copies of the original saved outputs used for comparison (`reference/`, 152 MB) | Duplicates of `verified_outputs/` apart from the documented exceptions | Their hashes are in `evidence/manifests_verified_runs/stage0_copies.json` |
| `.venv`, caches, IDE settings | Machine-specific | `00_setup_env.ps1` |
| The rest of the original project: exploratory and abandoned scripts, earlier runs, and the scripts for paper elements not re-run (SHAP, paired tests, one-hot and imputation ablations) | Not behind the reproduced results | Available from the author |

## Tools: package edition vs the versions used for the verified runs

`evidence/tools_as_run/` holds the tools exactly as used for the verified runs (sanitised). The package editions in `tools/` change only what is needed to run from any folder; no scientific step changed.

| Tool | Change in the package edition |
| --- | --- |
| `make_run_copies.py` | Regenerates `run_code/` from `original_code/` for any repository root (Windows or POSIX paths) and any BRFSS file location. It does not copy from the private project. Regenerating for the original folder reproduces the 14 execution copies of the verified runs byte for byte |
| `run_stage.py` | The repository root is the package folder. The BRFSS file is located through `data/brfss/`, `HS_BRFSS_XPT` or `--brfss_xpt`. `original_code/` is checked against the distribution manifest, and `run_code/` must have been generated for this folder. Adds `--steps` |
| `stages.json` | Same steps, scripts and arguments. The BRFSS path is relative, and the private project path is removed |
| `compare_outputs.py` | Compares with `verified_outputs/` instead of `reference/`; files not shipped are compared by SHA-256 |
| `published_vs_reproduced.py` | The middle column is the verified run (`verified_2026`); the published-vs-original table of the verified runs is kept in `evidence/reports/` |
| `check_env.py` | The comparison with the original `.venv312` is optional (`HS_ORIG_VENV`) |
| `verify_package.py` | New: checks the package checksums, the distribution copies, and that `run_code/` is the path-only transformation of `original_code/` |
| PowerShell scripts | No hard-coded user paths; `00_setup_env.ps1` takes `-Python` and also generates `run_code/` |
